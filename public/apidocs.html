API Y MCP PARA AUTOMATIZACIONES · ULTRA

Conecta el bot con tus propias herramientas.

La API de GBot expone la moderación, los miembros y las estadísticas de un grupo para que tus scripts, bots de la comunidad o paneles externos trabajen con el mismo motor que usa el panel. El mismo grupo además expone un servidor MCP para que un agente de IA use esas herramientas. Cada grupo tiene sus propias claves, sus propios ámbitos y su propio registro.

Empezar

1. Crea una clave en el panel

Abre el panel desde el bot, entra en Ajustes → Centro Premium → API y MCP para automatizaciones y crea una clave con el ámbito que necesites. La clave se muestra una sola vez: guárdala en tu gestor de secretos.

2. Llama a la API

curl https://gbot.webrom.cc/api/v1/me \
  -H "Authorization: Bearer gbot_live_…"

3. Revisa el registro

Cada acción de moderación hecha por la API queda en el historial del grupo, con el nombre de la clave que la originó.

Autenticación y ámbitos

CABECERA

Bearer

Cada petición incluye Authorization: Bearer <clave>. Una clave anulada deja de funcionar de inmediato.

ÁMBITO

Lectura

Permite consultar miembros, estadísticas, ajustes e historial de moderación. No aplica sanciones.

ÁMBITO

Moderación

Permite silenciar, expulsar, banear, avisar y revertir. Requiere además los permisos de administrador vigentes en Telegram.

LÍMITE

60 por minuto

Cada clave admite 60 peticiones por minuto. Las respuestas incluyen el margen disponible.

Las claves son privadas de cada grupo. La API solo responde mientras el grupo mantiene el plan Ultra y la clave no está anulada. Las acciones nunca superan los permisos de Telegram del bot ni de la persona que creó la clave.

Servidor MCP

El mismo grupo publica un servidor MCP con transporte Streamable HTTP en https://gbot.webrom.cc/mcp. Se autentica con la misma clave y respeta el mismo ámbito, así que un agente solo ve lo que la clave permite.

Conectar un cliente

{
  "mcpServers": {
    "gbot": {
      "type": "http",
      "url": "https://gbot.webrom.cc/mcp",
      "headers": { "Authorization": "Bearer gbot_live_…" }
    }
  }
}

Versiones del protocolo

El servidor habla la revisión 2026-07-28 y acepta también el saludo clásico de los clientes anteriores: 2025-11-25, 2025-06-18, 2025-03-26 y 2024-11-05. Con la revisión moderna cada petición lleva la cabecera MCP-Protocol-Version y el método server/discover devuelve las versiones admitidas.

Ejemplos

Miembros que participan poco

curl "https://gbot.webrom.cc/api/v1/members?limit=50" \
  -H "Authorization: Bearer gbot_live_…"

Silenciar a un usuario una hora

curl -X POST https://gbot.webrom.cc/api/v1/moderation \
  -H "Authorization: Bearer gbot_live_…" \
  -H "Content-Type: application/json" \
  -d '{"action":"mute","userId":123456789,"durationSeconds":3600,"reason":"Cuenta en observación"}'

Actividad de la última semana

curl "https://gbot.webrom.cc/api/v1/stats?days=7" \
  -H "Authorization: Bearer gbot_live_…"

Errores y seguridad

  • 401 falta la clave, es inválida o está anulada.
  • 402 el grupo ya no mantiene el plan Ultra.
  • 403 la clave no tiene el ámbito necesario o el actor carece de permisos vigentes.
  • 404 el grupo ya no está disponible.
  • 429 se superó el límite de 60 peticiones por minuto.
  • -32020 en MCP, la cabecera de versión no coincide con la del cuerpo.
  • -32022 en MCP, la versión de protocolo no está entre las admitidas.

No incluyas claves en URLs, capturas ni mensajes del grupo. Anula una clave en cuanto dejes de usarla: el registro del grupo conserva quién la creó y cuándo se anuló. GBot no envía datos de tu grupo a servicios de terceros al responder por la API.
